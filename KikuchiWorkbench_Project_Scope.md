# KikuchiWorkbench

**Proposed GitHub repository** `KikuchiWorkbench`  
**Release target** Native Windows 11 desktop application with an Ubuntu/Linux headless runner  
**Status** Scope for approval

## Project goal

Build a desktop workbench that takes a raw EBSD scan and candidate crystal structures through dynamical master-pattern simulation, orientation-dictionary generation, indexing, and inspection of the resulting phase and orientation maps. A new user should be able to run a bundled example, understand how the phase decision was made, and repeat the workflow on an Oxford Instruments or EDAX/TSL scan without editing simulation input files.

The primary scientific goal is to determine when two closely related cubic phases can be distinguished using full Kikuchi patterns. For phases with the same space group, band geometry can be very similar. Band widths and intensity distributions can add discrimination, while projection-center error, binning, noise, strain, and overlapping patterns can reduce it. The workbench will quantify these effects and report ambiguous pixels. Candidate phases will be supplied by the user. The first release uses detector-plane dictionary matching from master patterns. [Ram and De Graef, Acta Materialia (2018)](https://doi.org/10.1016/j.actamat.2017.10.069) · [Oxford Instruments phase discrimination](https://www.ebsd.com/ois-ebsd-system/advanced-phase-discrimination)

## Guided desktop workflow

| Step | User action | Application behavior |
| --- | --- | --- |
| 1. Open a scan | Choose an Oxford or TSL scan, or open the bundled example. | Detect the format and scan group. Show the map grid, pattern dimensions, bit depth, available raw/processed data, metadata sources, and a pattern preview. Flag missing inputs with export or calibration instructions. |
| 2. Add candidate phases | Load one CIF or a compatible EMsoft master per phase. | Show the crystal system, space group, cell lengths and angles, elements, sites and occupancies. Validate unit conversions, setting and origin, and supported EMsoft representations. Flag unsupported structures before simulation. |
| 3. Generate or reuse masters | Confirm beam voltage and specimen tilt. Choose a validated preset or edit advanced parameters. | Prepare the EMsoft crystal file, stage Monte Carlo and dynamical master jobs, show device checks, progress and logs, and verify the resulting HDF5 before adding it to the reusable master cache. |
| 4. Check detector geometry | Review the imported projection center (PC), detector orientation, binning and pattern crop. Compare a simulated pattern with a reference region. | Convert vendor geometry to a documented internal convention. Preview experimental and simulated patterns side by side and show an overlay or residual. Use a shared calibration for both competing phases. Record global or region-specific geometry. |
| 5. Build and match dictionaries | Set angular resolution in degrees, preview an ROI, then run the scan. | Sample symmetry-reduced orientation space. Estimate orientations, RAM, VRAM and disk use before launch. Project each master using the scan geometry, generate bounded chunks, and match experimental patterns on the selected compute device. Keep the GUI responsive and allow cancellation and reuse of compatible completed artifacts. |
| 6. Inspect and export | Select map pixels, inspect phase candidates, adjust a reporting threshold, and export. | Show phase, orientation/IPF, best score and phase-score margin maps. Show ambiguous and unindexed pixels separately. Display the measured pattern and best simulated pattern for each candidate phase. Export PNG maps, a tabular result and a machine-readable run manifest. |

Use a PySide6 desktop GUI with a guided path and expandable advanced settings. Provide a side-by-side raw/preprocessed pattern view. Keep measured patterns read-only and record the preprocessing pipeline, masks, resampling and selected pixels. The bundled example will work offline from an imported master. A separate tutorial will take users through native Windows master generation from CIF through HDF5.

## First-release input compatibility

| Source | Target input | Import and validation |
| --- | --- | --- |
| Oxford Instruments | Pattern-bearing `.h5oina` and supported uncompressed `.ebsp` | Inspect H5OINA for raw and processed datasets and prefer the raw dataset when available. Validate detector metadata, axes and scan order. For binary exports, use companion data or user-supplied geometry when needed. |
| EDAX/TSL OIM | Pattern-bearing EDAX H5EBSD, including verified `.oh5` variants, and supported `.up1`/`.up2` | Validate by file structure and version. Where binary layout or calibration data are missing, accept verified companion metadata or prompt for map dimensions and geometry. Preserve rectangular and hexagonal scan coordinates and missing points. |
| Test and simulation | Project fixture format and EMsoft simulated EBSD HDF5 | Load known geometries, orientations, phase labels and coordinates for reproducible benchmark runs. |

An orientation map by itself has insufficient information for full-pattern matching. When an input such as a standalone `.ang`, `.ctf`, or pattern-free HDF5 lacks images, explain how to export or pair the recorded patterns with their metadata. Treat vendor output orientations as optional comparisons. Test import against actual representative exports for both vendors and publish a supported-versions matrix. For significant PC variation across a scan, use validated region-specific dictionaries or request a smaller ROI. Record the PC approximation and its size when used. [kikuchipy input formats and known reader behavior](https://kikuchipy.org/en/v0.14.2/tutorials/load_save_data.html)

## Simulation and compute architecture

- **Crystal to master.** Convert a validated CIF to the pinned EMsoft crystal representation. EMsoft first simulates electron transport using Monte Carlo, then computes the dynamical EBSD master pattern using the transport results. Expose beam voltage, specimen tilt, and a validated preset for electron histories, energy and depth sampling, master resolution and diffraction parameters. Preserve complete effective inputs, units, executable version, output metadata and a checksum. Use positive and negative controls for CIF parsing, including equivalent axis settings, malformed occupancies and unsupported structural representations. Verify energy bins and projection/hemisphere metadata on import. Where a verified adapter supports energy weighting, record the applied weighting. Validate the approach against an EMsoft reference projection before using it for phase comparisons. [EMsoft Monte Carlo](https://github.com/EMsoft-org/EMsoft/wiki/Monte-Carlo-Simulations) · [EMsoft master patterns](https://github.com/EMsoft-org/EMsoftOO/wiki/EBSD-Master-Pattern-Simulations) · [Reproducible EMsoft input and output example](https://zenodo.org/records/20376828)
- **Native Windows simulation.** Start by proving a pinned EMsoft release/build can execute the crystal conversion, Monte Carlo and dynamical stages natively on Windows 11 with a compatible OpenCL device. Verify executables, DLLs, HDF5 data and device drivers on a representative machine, with a documented offline installation. Evaluate EMsoft 5 first and select the exact revision from measured compatibility. Prevent a release claim for native generation until this workflow passes on Windows. Document simulation-device requirements separately from dictionary compute. [EMsoft releases](https://github.com/EMsoft-org/EMsoft/releases) · [EMsoft SDK build instructions](https://github.com/EMsoft-org/EMsoftSuperbuild)
- **Dictionary projection and matching.** Use kikuchipy for supported readers and projection and orix for symmetry-aware orientation sampling. Begin with normalized cross-correlation using a consistent preprocessing policy and angular coverage across competing phases. Keep top candidates per phase, even when the overall top matches all belong to one phase. Process observed patterns and simulated orientations in chunks. The proposed matching implementations are NumPy/BLAS on CPU and optional PyTorch CUDA on supported NVIDIA hardware. Offer Auto, CPU and GPU selection. Auto retries recoverable device/memory failures with smaller chunks or CPU and records the actual backend. Use a 4 GB workstation GPU as the initial low-memory test target. Cache completed dictionaries only when requested or helpful, and invalidate them when master, geometry, orientation sampling, masks or preprocessing change. [kikuchipy dictionary indexing workflow](https://kikuchipy.org/en/stable/tutorials/pattern_matching.html)
- **Shared application core.** Both GUI and headless CLI call the same import, calibration, simulation, projection, matching and export services. Use isolated job folders with status, logs and validated outputs. Keep interrupted artifacts out of the cache. Use a versioned manifest to record inputs, projection conventions, parameters, software, hardware, thresholds and exports. Build an offline Windows installer or portable bundle after the native workflow is proven. The Linux runner will support scripted demo, benchmark and batch indexing runs.
- **Phase decision.** Compare the best score for each candidate phase and retain the runner-up and score margin. Use a low absolute match score for unindexed pixels and a small separation between plausible phases for ambiguous pixels. Report orientation fit separately from phase separation. A score margin is a ranking diagnostic. Treat it as a probability only after separate calibration and validation. If local orientation refinement is enabled for phase discrimination, give each phase the same refinement search budget and hold the calibrated detector geometry fixed across phases.

## Validation and release criteria

| Check | Dataset or environment | Deliverable and pass condition |
| --- | --- | --- |
| Fast cloud and CI smoke tests | Small deterministic bundled fixtures, CPU-only Linux and Windows runners | A complete load → project → match → export run without network or GPU after environment setup. Verify exact-grid orientation recovery up to symmetry, expected clean phase labels, ambiguous ties, bad-pattern rejection, and input/format errors. Run a separate GUI launch and bundled-demo smoke test on Windows. |
| Native simulation integration | Windows 11 with compatible OpenCL and a known cubic reference crystal | Run CIF → verified crystal → Monte Carlo → validated master → detector projection. Repeat the reduced job headlessly on a supported Linux/OpenCL runner where provisioned. Record binaries, data and tolerances against the reference. |
| Controlled cubic discrimination | Reproducible simulated Ni and Cu endmembers, both FCC with space group Fm-3m and approximate lattice parameters 3.524 and 3.615 Å | Publish the CIF and generation recipes and a compact two-phase grid with held-out, off-grid orientations. Add a same-chemistry lattice-parameter sweep to isolate width sensitivity, and identical competing masters to check ambiguity. Stress-test PC offset, noise, binning, angular step, crystal orientation and mixed-pattern regions. The Ni–Cu endmembers are a simulated classification exercise using public crystal parameters. [Ni reference master](https://zenodo.org/records/7498645) · [Cu lattice parameter source](https://theses.lib.polyu.edu.hk/bitstream/200/6734/1/b25301354.pdf) |
| Real-data interoperability | Public Oxford Al–Si raw `.ebsp` and EMsoft Al/Si masters. Add a verified TSL scan with raw patterns, public if available or approved for private testing. | Compare a documented ROI with published Oxford results and carry out an equivalent TSL import-to-export check. Both vendors require tests for input order, coordinates and PC conversion. Al–Si exercises real data ingestion and phase mapping. Its result is reported separately from the same-structure benchmark. [Public Al–Si data and masters](https://zenodo.org/records/20290635) |
| CPU/GPU parity and resource use | Identical fixture on cloud CPU and a supported CUDA workstation or runner | Compare scores within measured numerical tolerances and require phase/orientation agreement for well-separated candidates. Test near-ties and deterministic ordering, report actual fallback behavior, and record time, throughput, peak RAM and VRAM. |
| Beginner and offline acceptance | Clean representative Windows 11 workstation | After installation a beginner can complete the supplied example and export results using the quick start. Repeat with approved scan inputs from both vendors. Run a separate CIF-generation walkthrough on the stated OpenCL configuration without internet access. |

Report confusion matrices including ambiguous/unindexed counts, per-phase recall, coverage versus error, symmetry-aware orientation error, score margins and compute cost. Pick phase decision thresholds on development fixtures and freeze them before held-out runs. Include at least one realistic mismatch between target patterns and dictionary projections, such as a separate EMsoft detector-pattern generation route or perturbed geometry and acquisition conditions. Record actual results and failure regimes, including the smallest tested lattice contrast resolved under each condition. Experimental discrimination for the lab’s eventual pair will require an independent reference, such as EDS/WDS or known phase standards.

## Implementation milestones

1. **Feasibility and formats.** Confirm the native Windows EMsoft chain and offline dependencies. Verify Oxford and EDAX/TSL fixtures and lock detector/reference-frame conventions. Record approved benchmark inputs, redistribution terms and checksums.
2. **Headless scientific workflow.** Implement the shared core and run the small CPU demo from existing masters. Add deterministic fixtures, visual reference comparisons, and cloud CI. Connect CIF and EMsoft jobs.
3. **Dictionary and phase validation.** Add batched CUDA/CPU matching, comparable per-phase scoring, ambiguity and the controlled cubic benchmarks. Verify numerical parity and low-memory behavior.
4. **Desktop release.** Add the guided workflow, map/pattern inspection and exports. Complete the beginner guide, offline Windows installation, vendor export instructions, advanced parameter reference, CLI reproduction guide, troubleshooting and benchmark report.

Scope for later releases includes spherical-harmonic indexing, TKD, strain or composition regression, and quantitative decomposition of overlapping patterns. [Spherical-harmonic EBSD indexing](https://doi.org/10.1016/j.ultramic.2019.112841)
